## 2024-05-24 - [Avoid in-memory JPA entity filtering]
**Learning:** Found a pattern where related JPA entities (order details) were being fetched individually inside a loop iterating over parent entities (orders) and manually filtered in Java. This results in severe N+1 query performance degradation and massive object instantiation overhead, as seen in `hasUserPurchasedProduct`. Furthermore, when writing JPQL queries for existence checks, `CASE WHEN EXISTS (...) THEN true ELSE false END` is vastly superior to `COUNT(...) > 0` as it allows the database to short-circuit upon finding the first match.
**Action:** Replace in-memory filtering iterations over collections and N+1 repository lookups with single `EXISTS` JPQL queries that let the database handle the filtering optimally.
