## 2024-11-20 - [Replace N+1 In-Memory Collection Filtering with Database Exists Query]
**Learning:** Found a severe anti-pattern in `DonHangService.hasUserPurchasedProduct` where it was checking if a user purchased a product by fetching all their orders, iterating through them, checking their status in memory, then fetching all order details for each order, and iterating through those in memory to find a matching product ID. This O(N*M) manual filtering with N+1 queries is disastrous for performance.
**Action:** Always delegate collection filtering, existence checks, and aggregations to the database using JPQL (e.g., `COUNT`, `EXISTS`, `SUM`) rather than pulling entities into memory to filter them in Java. Replaced the manual loops with a single, efficient `EXISTS` (via `COUNT(c) > 0`) query.
